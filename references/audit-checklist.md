# BEM audit checklist

Run each rule over the target files. For every violation emit one line: `file:line — rule — before → after`. Group the report by file. End with a count of auto-applied fixes vs flagged-only items.

Audit every in-scope file **in full**, not only the lines a diff/PR changed. A pre-existing blank line between siblings, comment, flat pseudo, or combinator selector is still a finding — read each file top to bottom.

## Stylesheet rules (.scss / .css)

1. **Tag or id selectors** — any selector targeting a bare element (`div`, `a`, `h2`, `ul`, `p`, `button`, `img`...) or an id (`#hero`). Tags allowed only inside a clearly scoped reset/normalize file; ids never. → rewrite to a class (the element keeps its `id` in markup for anchors/JS, but a class does the styling), or flag if no class exists. Exception (project-overrides layer only, if opted in): a bare `svg`/`svg path`/`svg circle` reached off a component class purely to set paint (`fill`/`stroke`/`color`) on an inlined icon — do not flag when the project sanctions that idiom.
2. **Class-in-class nesting** — a class selector nested inside another rule. → unnest to a top-level rule. Safe to auto-apply.
3b. **Combinator across classes** — a descendant (`.a .b`), child (`.a > .b`), `:has(.class)`, or a chained modifier pair (`.block--a.block--b`) used to style one element from another element's presence/state. It is nesting by another syntax; the style no longer lives at its own single name. → replace with one flat modifier on the styled element, toggled in markup (via the project's class-name helper): a parent reacting to a child → `.parent--with-child`; a child styled inside a parent state → `.child--state`. Rename fix (markup + style together) — flag unless `--rename`.
4. **Illegal nesting** — anything nested that is not a `:`/`::` pseudo, an at-rule (`@media`, `@container`, `@supports`), or the theme mixin's `@at-root` light-theme override. The theme mixin is never a violation even though it emits `@at-root .light-theme &` — it is the same class's value under another theme, not a new class. → unnest only genuine class-in-class.
5. **Nesting depth > 1** — a pseudo or media query containing further nested blocks. → flatten to one level.
6. **Flat pseudo/breakpoint** — a pseudo-class/element or an at-rule (`@media`/`@container`/`@supports`) written as its own standalone top-level rule (`.block:hover { }`, `.block::after { }`) instead of nested under its block with `&`. → fold into the block. Safe to auto-apply.
7. **Wrong order inside a rule** — declarations and groups not in the fixed order: plain declarations → theme `@include` → (blank line) → `&:`/`&::` pseudo groups → `@media`/`@container`/`@supports`. → reorder to match. Safe to auto-apply.
8. **Element chaining** — `block__a__b` (more than one `__`). → flatten to `block__a-b`. Rename, so flag unless `--rename`.
9. **Block name repeated** inside its own element beyond the single `block__` prefix. → flag rename.
10. **Shared block modifier nested under a page block** — a shared block's modifier (`.btn--red`, `.gradient-text--orange`) written inside a page block's rule instead of as its own top-level rule. This is the stylesheet-side mirror of markup rule 22. → unnest to a top-level rule; the shared block is varied only through its own top-level modifier, never restyled from inside a page block. Safe to auto-apply the unnest; flag if it requires renaming.
11. **Abbreviated names** — `desc`, `col`, `bg` etc. inside a class. → flag rename, propose full word. Exception: an established shared block (`btn`, `gradient-text`, ...) is a reusable block in its own right, not an abbreviation — never flag or rename it, customize via modifiers only. See the shared-block test in SKILL.md core rule 2 (used in ≥2 blocks / lives in shared location / carries no page name); when ambiguous, flag as ambiguous rather than assuming.
12. **Inline / single-line rule** — a rule collapsed to one line (`.x { color: red; }`). → expand to one declaration per line, braces on their own lines. Safe to auto-apply.
13. **Blank line between sibling top-level rules.** → collapse. Safe to auto-apply. Keep at most one blank line inside a rule separating declarations (and the `@include`) from nested groups.
14. **Stray theme/responsive values** — a class's dark/light or breakpoint values living in a separate theme block or media bucket instead of inside the class. → move into the class block.
15. **Modifier format** — modifier not written as `--kebab-case` (e.g. `--withArrow`, `--Title`). → flag rename.
16. **Comment in a stylesheet** — any `//` line comment or `/* */` block in a `.scss`/`.css` file. Flat, fully-spelled, one-property-per-line rules are self-describing, so section banners (`// Sidebar`, `// Footer`) and explanatory notes only drift from the code they label. → remove. Safe to auto-apply. Exception: a license/SPDX header at the very top of a vendor or reset file.
17. **Fractional pixel value** — a layout `px` length with a decimal (`bottom: -344.5px`, `width: 87.4285px`) on a size/spacing/position property (`width`, `height`, `padding`, `margin`, `top`/`right`/`bottom`/`left`, `gap`, `border-width`). Almost always a design-tool export artifact; rounds to a blurry sub-pixel. → round to the nearest integer. Safe to auto-apply. Does NOT apply to deliberate sub-pixel design tokens in other properties/units (`letter-spacing: 1.2px`, percentage gradient stops, `em`/`rem`/`%`).
18. **Magic-pixel full radius** — `border-radius` faking a fully-rounded shape with an oversized pixel value (`9999px`, `999px`, `100px` "big enough"). → use a percentage: `50%` for a circle/dot (equal width/height), `100%` for a pill/capsule. Safe to auto-apply. A real fixed corner radius (`border-radius: 12px`) is untouched.
19b. **Dead or redundant declaration** — a property set to the value it already has by default with nothing to override it: `padding: 0`/`margin: 0` on an element with no non-zero value set anywhere (bare `<div>`, undecorated grid/flex container), a property duplicating the browser default (`display: block` on a div, `position: static`), or a value repeated identically within the block. → delete. Before removing, confirm nothing overrides it — grep the class + its siblings, the mixins it `@include`s, and any parent rule; a `padding: 0` that cancels a `modalBody()` mixin's padding is real work, not dead. Safe to auto-apply once confirmed; flag when the override is ambiguous.

## Markup rules

20. **Block matches file name** — the top-level block class equals the file/component name (`pricing.ejs`/`pricing.scss` → `.pricing`, `SlidingTooltip.jsx` → `.sliding-tooltip`), and sections derive from it as `block__section`. → flag mismatch as rename.
21. **Class naming consistency** — markup classes must match the block/element/modifier in styles, no abbreviations. → flag rename across markup + styles + JS together.
22. **Shared block not mixed with page class** — a shared block (`btn`, `gradient-text`, ...) must not carry a page element class on the same node (`class="pricing__hero-cta btn"`). → flag; resolve via the block's own modifier or a page wrapper around it. (Stylesheet mirror: rule 10.)
23. **Orphan classes** — a class in markup with no matching rule, or a rule with no markup user. → report, do not delete without confirmation.

### Behavior hooks (all stacks)
24. **JS selecting by a style class** — a script, test, or analytics snippet reaching an element with `querySelector('.block')`, `getElementsByClassName`, or an e2e selector built on a styling class. → add a `data-js-<name>` attribute to the element and select by `[data-js-<name>]`; the class stays for styling only. Touches markup + JS together — flag unless `--rename`. (Core rule 14.)
25. **A `data-js-*` attribute used in a stylesheet** — any selector containing `[data-js-...]`. Behavior hooks are never styling hooks. → style the element's class instead. Safe to auto-apply when the element already carries a class; flag if a class must be added.

### Tokens
26. **Literal where a token exists** — a hardcoded color, gradient, font stack, or page width that already has a variable in the project's tokens file. → replace with the variable. Safe to auto-apply on an exact or near-exact match; when the closest token differs materially (visibly different hue, substantially different size), surface both options and ask rather than substituting or hardcoding. (Core rule 15.)
27. **Literal breakpoint** — a `@media` width written as a raw value (`768px`) instead of a named breakpoint variable. → replace with the token. Safe to auto-apply when a matching token exists; flag only when the project has no breakpoint scale yet — inventing one is the user's call. (Core rule 16.)

### Reuse mechanism
28. **Mixin standing in for a shared block** — a styling mixin `@include`d by blocks whose markup the project controls, where a shared block class would carry the same styles under a name visible in the DOM. → convert to a shared block. Leave alone: a mixin for third-party/generated markup that cannot take a class, a fragment meaningless as a DOM name (`ellipsis`, `center-content`, `placeholder`), and a shared base that several named blocks build on. Flag, never auto-apply — the fix is a markup change. (Core rule 17.)

### Static-page markup (.html / .ejs)
29. **Div standing in for a semantic element** — a `div` carrying content that has a real tag (`section`, `header`, `nav`, `main`, `footer`, heading, `p`, list, `a`, `button`). → propose the tag swap; structural, so flag rather than auto-apply. (Core rule 18.)
30. **Heading outline broken** — more than one `h1` on a page, a skipped level (`h2` → `h4`), or a heading level chosen for its font size. → flag; size headings with a class, not by picking a different level.
31. **Interactive handler on a non-interactive tag** — `onclick`/a JS listener on a `div` or `span` where `button` or `a` belongs. → swap the tag; flag, as it changes behavior and focus order.
32. **Missing accessibility attribute** — `img` without `alt`; `a[target="_blank"]` without `rel="noopener noreferrer"`; `html` without `lang`; an interactive or landmark element missing the `aria-*`/`role` it needs; no visible focus state. → add it. Safe to auto-apply; use an empty `alt=""` only for a decorative image and say so in the report.
33. **Page id present** — the page root element carries an `id` named for the page alongside its block class, where the project uses page ids for analytics. Other `id`s (sections, anchors, `aria` targets) are free and never flagged — the only id violation is a *style* hung on one (rule 1).
